# 京客导出助手

Windows 微信聊天读取、会话浏览、多格式导出，以及逐联系人的 AI 重要记忆提炼到 Obsidian。当前版本 **0.14.0**。

## 0.14.0：自动发现账号，直接读取（2026-10-25）

默认操作为：**打开助手 → 自动发现本机微信账号 → 选择账号并点击下一步 → 自动读取并进入聊天**。无需在主流程指定文件夹。已读账号可直接进入；多个账号需明确选择。

后台从微信自身路径配置、Windows 微信注册表、系统文档位置和本地磁盘常见目录识别实际账号，支持微信记录存到自定义盘符。账号查询使用后台结果快照，发现过程不会递归扫描附件内容。未找到时可打开官方微信、完成登录，软件会继续检测；也可点击重新检测。

首页会显示已发现但尚未读取的账号。手动指定目录、iPhone 本地备份及原导出器缓存移到「高级导入」。读取失败保留可见原因与重试入口，不自动切换到另一个账号。

REA 原生证据与空配置 Windows 实际运行记录见 [自动发现账号与操作流程 0.14.0](docs/京客导出助手-自动发现账号-0.14.0.md)。当前可访问环境已通过配置自动找到真实账号；另一台 G 盘电脑的发现与大库完整性仍需在那里运行确认。

## 0.13.0：原生会话工作台与增量同步（2026-10-24）

- 聊天页按参考截图重做为约 250px 会话侧栏、联系人真实姓名与头像、灰色消息区、绿色发出气泡；记录目录和 AI 整理移至次级入口。
- 选择 `WeChat Files` / `xwechat_files` 总目录或账号目录时，只读实际微信联系资料、会话、头像、消息分库；不再把附件中的 JSON、日期或文档文件名当成联系人。历史混入的文档会话保留在资料库中，默认列表隐藏。
- 「全量刷新」重新读取当前会话；「仅读新消息」按消息本地 ID 游标追加。自动同步每 3 秒检查当前数据源数据库及 WAL 变化，暂停开关可停止后台读取。
- 微信持续追加 WAL 时冻结已存在的日志边界，校验完整提交；基础数据库未变时更新已认证的私有副本，避免每次复制和解密整个大库。日志换代、基础库变化或副本失效时重新获取完整副本。
- 消息附件先按当前页证据查找，图片预览不等待扫描百万媒体目录。不能确认归属或尚未下载的附件仍明确显示未读出。

REA 已取得原程序 `AppendNewMessages` 和 `RefreshSession` 的原生函数证据，区分消息游标追加与全量会话刷新。本项目使用独立 Python 实现。原程序会员、短信登录和云端语音服务未接入。

实际 Windows 小库结果、截图及完整边界见 [0.13.0 读取与界面对照](docs/京客导出助手-原生会话与实时读取-0.13.0.md)。用户截图中的 `G:\微信聊天记录\WeChat Files` 位于另一台 Windows，当前环境无法据此证明该大库的数量、图片或新增消息完整性。

## 0.12.0 历史进展（2026-10-24）

已借助 REA 分析参考软件并在 Windows 微信 4.1.15.56 的当前已登录账号上实际读取：4 个会话、12 条本地联系人资料、6 条消息；修正后一次读取约 8.89 秒，无读取错误。本人发送方向已核对，Markdown 原文与 Excel 通讯录已实际导出。

## 0.11：多库连接和原程序缓存继续补齐

- 修复只读连接器找到第一个有效材料就结束扫描的问题，继续收集未匹配数据库的材料，报告匹配进度和部分匹配状态。
- Windows 目录先检查读取连接，再复制加密库全文；连接未就绪时明确报告，已有可用副本仍可复用。
- 自动查找原程序常见本地缓存；缓存读取恢复已保存的联系人名称，并保留同步完整性说明，部分缓存不会冒充全部历史。
- 真实数据库副本在当前 Windows 虚拟机实际执行读取：约 0.215 秒报告当前没有微信进程，28 个未连接库延后复制，0 条聊天读出。这是连接诊断结果，尚未完成全量解密。

实现与实际结果见 [多库连接与缓存读取 0.11.0](docs/京客导出助手-多库连接与缓存读取-0.11.0.md)。

## 0.10：解决长时间“读取数据中”的加载路径

- 参考 REA 确认的原程序分页、消息缓存和当前页媒体准备方式，聊天按每 500 条保存，不再等待全目录媒体转换；后台读取时可查看已提交记录。
- 未变化且已完成的文件复用已有记录；未完成文件下次重读并去重。界面显示文件名、文件序号、条数、字节/页数和耗时，并支持取消。
- 预览才解码媒体，明确导出时处理所需附件；每秒进度轮询不再统计整个资料库。
- 新增原导出器 `msg_rows` 本地 SQLite 缓存格式读取，复用其已解析数据；尚无真实缓存兼容性验收。
- 私有缓存包含已解密数据库，保存在本机资料库 `source-cache`，不进入发行包。0.9 升级后的首次重新读取会建立新检查点。

实现、证据和限制见 [加载改造 0.10.0](docs/京客导出助手-加载改造-0.10.0.md)。本轮不把媒体登记速度当作全部聊天数据库加载速度。

## 0.9：媒体读取、预览与导出

- 新增“媒体文件”入口，可在聊天数据库暂时未读通时单独读取所选目录的媒体。
- 支持旧版 XOR DAT、V1/V2 AES 分段图片格式，以及 WXGF 的 HEVC 图像段转换；V2 新增本地 kvcomm 账号材料的自动推导，候选通过块头与完整内容校验后才显示。此路径尚无真实 V2 样本验收，不能保证所有新版图片可读。
- 集成开源 Pillow、pysilk-mod 和独立 FFmpeg：SILK/AMR 等语音转换为 WAV，视频转换为浏览器可播放的 H.264/AAC MP4。
- 消息中的媒体标识会被保留，用 MD5/文件标识关联本地附件；无法确认归属的文件保留在媒体列表，不推测联系人。
- 已关联附件可在聊天内显示/播放，并随 HTML、Markdown、PDF、JSON、表格或纯文本导出。媒体文件也可单独导出。
- iPhone Finder/iTunes 备份提取新增常见图片、语音、视频文件；微信自带专用备份按官方教程先恢复/迁移到电脑版微信，再读取账号目录。

本轮在 Windows 使用用户提供目录的媒体副本实际读取：75 个候选，71 个图片记录、2 个视频记录成功解码，2 个 DAT 尚未识别。导出 73 条媒体记录，按内容去重保存为 64 份实际媒体文件，并附清单，导出错误为 0。此结果不代表聊天数据库已读通，也不代表媒体已正确归属联系人。SILK、WXGF 和新版 AES 图片尚未在该批真实数据中得到验收。详细记录见 [媒体实现与实际结果 0.9.0](docs/京客导出助手-媒体实现与实际结果-0.9.0.md)。

## 0.8：记录副本与加密日志读取

继续使用 REA 取得原程序的 `applyWAL`、`decryptPageInto`、`DecryptFile`、`scanDatabaseKeys`、`ArmEarlyHook` 和 `managed.status` 六个函数的原生伪代码与汇编。结合 SQLite / SQLCipher 的公开格式规范，独立实现临时副本中的标准加密 WAL 合并。完整说明见 [读取与日志合并 0.8.0](docs/京客导出助手-读取与日志合并-0.8.0.md)。

复制数据库及相邻 WAL 时检查文件增删、元数据和两次内容散列；持续变化时最多重试三次。日志检查头、盐与累积校验，选择最后一次完整提交，按数据库页号逐页验证 HMAC，最后检查解密副本。读取报告显示逐库结果和日志提交数量。未提交或旧代日志尾部单独说明，回滚日志暂不恢复。

本次未运行自动测试，也未完成真实微信 4.1.15.55 的读取验收；新 WAL 实现仍需真实数据验证。上述复制检查用于发现常见并发变化，不提供原子文件系统快照保证。

## 0.7：选择账号、登录与读取流程

首页现在按「数据准备 → 选择账号 → 导出与整理」组织。点击「添加新的微信 / 备份」可以自动发现常见记录目录、选择文件夹或填写目录；已读到聊天的账号显示缓存状态，可以直接进入。

新账号读取过程显示检查目录、等待登录、连接记录、读取聊天与账号确认。读取成功后点击「查看记录」进入对应账号的聊天工作台；每个账号可以设置导出目录。切换账号后，会话和当前列表的 AI 提炼范围随之切换。

Windows 上可打开已安装的官方电脑版微信。需要重新连接时，可选择等待手动重开；也可以先确认已完成消息同步、保存编辑内容，再点击「重启微信并读取」。只有该明确操作会关闭当前用户、同一可执行文件的微信进程。正常读取不会重启微信。

扫码登录在官方电脑版微信窗口完成。本项目未接入轻虾的商业服务账号、短信或会员后台。微信进程存在只显示「运行中」，不代表已经登录或记录可读；账号就绪以实际已导入消息为依据。

原程序主 EXE 的 REA 原生连接已恢复，新增账号状态函数已取得伪代码；恢复结果和独立实现的对应关系见 `docs/京客导出助手-账号流程-0.7.0.md`。微信 4.1.15.55 的真实数据读取仍需独立验收，不能把 UI 和打包成功当成兼容性通过。

## 从 GitHub 源码运行（Windows）

仓库：[787896255-pixel/weixin](https://github.com/787896255-pixel/weixin)。本仓库保存源码、界面资源、第三方许可和合成演示数据；`dist/` 中的 Windows 便携包不随 Git 提交上传。

安装 Python 3.13（64 位）和 Edge WebView2 后，在 PowerShell 执行：

```powershell
git clone https://github.com/787896255-pixel/weixin.git

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe launcher.py
```

需要在 Windows 构建独立程序时，可运行 `build_windows.ps1`。下文提到的便携版 ZIP 为本地构建产物，直接克隆源码不会得到该 ZIP。

## 使用

解压 `dist/JingkeExporter-0.14.0-Windows-x64.zip`，在 Windows 双击 **启动京客导出助手.cmd**。包内含 Python 和 Windows 依赖，无需另装 Python。

1. 在电脑微信登录后打开助手，等待自动发现账号，选择账号并点击「下一步」；软件会读取并进入聊天页。已有记录或备份文件可从「高级导入」处理。
2. 左侧按账号、联系人/群聊过滤，点击查看，或勾选多个会话。
3. 会话顶部可搜索、全量刷新、仅读新消息；「消息筛选」可按日期、类型、发送方向筛选及勾选消息。
4. 在「导出中心」选择范围、格式、输出目录、每份消息数，点击「开始导出」。
5. 如需重要记忆，设置 AI 与 Obsidian，点击「提炼此人并保存」或「AI 提炼并保存全部」。

「演示模式.cmd」加载合成数据，使用独立资料库。原生窗口依赖 Edge WebView2，也可用「浏览器模式.cmd」。

## 界面

按用户指定的轻虾导出助手蓝白桌面风格重新制作首页、导航、聊天工作台与导出弹窗。聊天默认展开，AI 重要记忆位于独立页签。三张蓝色立体插图为本项目新生成，标准界面图标使用 MIT 许可 Tabler Icons。

## 导出

- HTML、PDF、Excel、TXT、Markdown、CSV、JSON、JSONL。
- 当前会话、勾选会话、当前列表；筛选条件共享，可自动拆分。
- 每次生成新的输出目录，包含导出清单；不会覆盖历史导出。
- PDF 使用本机 Edge/Chrome，保留 HTML 源文件；缺少渲染器时说明失败。
- Excel 作为文本写入，长消息分段，避免单元格截断。
- 通讯录为已读取会话联系人和群聊，不代表完整好友列表或全群成员。
- 定时导出支持一次/每天/每周，运行期间执行；增量依据本软件新导入的消息。需先再次读取微信数据。

## AI 与 Obsidian

支持 Chat Completions 兼容接口。逐人分析全部已导入聊天，提炼事实、决定、约定、待办、偏好、事件，按工作/生活/其他归档，保留原文依据和消息编号。

保存到所选库的 `微信第二大脑/人物/`、`微信第二大脑/分类/` 与 `重要记忆索引.md`。重命名软件后保留原路径与 `%LOCALAPPDATA%\WeChatBrain`，继续使用已有数据。

API Key 和读取访问材料仅留在本次运行的内存。点击 AI 提炼时，所选人的聊天内容会发送给你配置的模型服务。手动修改过的 Obsidian 文件会保留，并在报告中列出冲突。

## 读取范围与当前限制

沿用项目内 `chatlog_extract.py`、`chatlog_platform.py`，并包含公开许可读取适配。支持的路径包括 Windows 微信目录、明文导出、iPhone Finder/iTunes 本地备份。检测到目录不等于已成功解密。

- Windows 微信 **4.1.15.55 尚未完成真实账号读取验证**。
- 现有读取器有只读进程连接及可选 4.x 启动连接；失败时可复制诊断。
- 0.6.1 新增数据库入口捕获，并保留原计算入口捕获；所选加密库逐个校验，显示“校验 X / Y”。这两种入口尚未在用户真实 4.1.15.55 进程验证。
- 标准加密 WAL 已有完整提交合并实现；副本持续变化、日志校验失败或存在回滚日志时，正常退出微信后重试。连接信息仅在本次运行内存中保留。
- 微信专用“备份与恢复”包未通用适配；iPhone 加密备份需要原备份密码。
- 未读出或无法关联的媒体仍显示占位；语音转文字尚未实现。媒体格式与实际结果见 0.9 说明。
