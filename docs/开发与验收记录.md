日期：2026-10-22（Asia/Shanghai）

## 0.4.0：处理原电脑读取失败与 4.1.15.55 版本反馈

用户反馈 14 个库未读出，且确认是在本人电脑，随后提供版本号 4.1.15.55。不能据这个通用错误判断未在原电脑或未登录；也不能仅凭版本号推断实际操作系统。

### 修复与新增

- 删除导入器「无匹配材料就要求原机登录」的统一归因；连接诊断保留实际系统、进程版本／位数／同一用户／模块检测、OpenProcess 错误码、读取失败和时间／扫描量等数据。未读取的原因分别报告，具体用户根因仍待原机诊断。
- 对照 Chatlog 固定提交的 `v4_windows.go`，补入 4.x 可写私有内存中的指针结构查找。保留同一用户、只读访问和所选数据库 HMAC 校验约束。
- 新增 `wechatbrain/windows_capture.py`、`capture_v4.js`，适配 wechat-decrypt 固定提交 `f0b3f9f95dda2d954ee3dbe1d139fb1944a5ecfd` 的启动阶段连接办法。由用户明确点击入口并手动重开微信；不复制其自动 taskkill 和写入 key 文件行为。Frida 连接仅针对当前用户新启动的 Weixin.exe，候选必须匹配所选库；结果仅留内存，结束后 detach。
- 内置 PyPI Windows x64 Frida 17.24.3，随包保留第三方许可证。MIT 来源和修改说明见 `THIRD_PARTY_NOTICES.txt`、`third_party/wechat-decrypt/LICENSE`。
- 界面增加系统／软件版本标识、可选 4.x 连接按钮和「复制读取诊断」。诊断导出严格选择公开状态字段，不包含聊天、账号路径、密钥、模型凭据或原始脚本消息。诊断 JSON 只保存在本地资料库。
- 逐库结果区分无匹配材料、WAL 未合并、页面认证失败、文件不完整与解密后数据库检查失败；SQLite／文件读取异常按库隔离，避免吞掉具体原因或中止所有会话读取。

### 完成范围

本次完成源码语法检查与 Windows 便携包／源码包组装，未新增或运行测试套件，也没有连接用户原 Windows 电脑。启动连接办法并未在 4.1.15.55 原机上验证；不声称真实数据已成功解密。需要用户运行新版后，通过诊断判断实际平台、客户端、访问错误或捕获／校验结果。

## 0.3.0：开源 Windows 读取能力适配

### 实际改动

- 适配 `imldy/chatlog` 提交 `a7162bca9454fa43b5950a2414670983fe180e56` 的 Windows 3.x 模块／指针读取及 SQLCipher 派生、HMAC 校验实现；新增 `wechatbrain/windows_reader.py`、`wechatbrain/sqlcipher.py`。Apache-2.0 许可证和来源、修改说明保存在 `third_party/chatlog/LICENSE`、`THIRD_PARTY_NOTICES.txt` 并随便携包分发。
- 修正原始进程数据与派生 AES 密钥的区别：十六进制材料分别尝试直接密钥及 PBKDF2 派生，经所选数据库 HMAC 与解密页头核验后才接受。Windows 3.x 使用 SHA-1／64000 轮，4.x 格式使用 SHA-512／256000 轮。
- Windows 定向读取只访问当前用户的微信进程；辨认 32／64 位目标；不写微信进程、不输出密钥；保留时间、读取量和取消边界。该逻辑尚未在登录对应真实账号的 Windows 上运行验证。
- 解密按页流式输出，校验每页 HMAC，再执行 SQLite quick_check；加密 WAL 尚未合并时拒绝导入该库并说明，不静默丢弃日志。
- 桌面导入改用新解密器；保留 DeepSeek 引擎进行消息与联系人结构解析。新增 `.bakdb` 识别、保留账号目录名，使用规范文件 URI 打开数据库，修复本次 `xInfo.db` 无法打开的问题。
- 已有合成加密样本此前填充了随机 HMAC，不符合新验证规则。本次修正生成器并重新生成该合成样本的真实 HMAC；这项操作不涉及用户数据库，也不代表运行了测试。
- 导入报告增加已识别／成功解密数量、未读文件清单与 `locked` 状态，避免把没有读出内容报告为读取成功。原始账号目录与工作资料库加入源码排除规则；源码发布采用明确文件清单。

### 本次真实目录读取结果

已实际调用新版导入器读取用户提供的账号目录。含历史 `.bakdb` 在内发现 29 个数据库候选，其中 28 个为加密库；1 个明文辅助库可打开但不含可识别聊天。当前没有匹配的解密材料，也没有原 Windows 微信进程，结果为 `locked`、0 条消息、0 个联系人。

详细读取报告保存在本机 `.wechatbrain/wxid_private_account-import-v0.3.0/read-report.json`，不打入源码包或便携包。没有调用外部 AI，也没有生成真实人物笔记。

本次未新增或运行测试套件。源码语法检查、便携包组装的结果与真实 Windows 登录账号的读取成功是不同层次；本次不声称已完成后者。下文 21 项检查对应 0.2.0，Windows 运行证据对应 0.1.0。

## 0.2.1：确认并补齐 DeepSeek 读取代码接入

本次补齐桌面导入器与原读取器的格式规则一致性：文件后缀及跳过目录改为复用原模块常量，补入此前桌面扫描遗漏的 `.sqlite2`、`.text`、`.chat`、`.msg`、`.xhtml`。Windows 便携包继续包含这两份读取源码，并在随包说明中注明；重新组装为 0.2.1。

## 本次确定的需求

用户要求简化为：读取微信聊天记录，AI 分析每个人的聊天，提炼重要内容落盘到 Obsidian。软件面向 Windows，本机目前没有用户的真实聊天记录。

## 这版实际完成

- 主界面只保留「读取聊天记录」「AI 提炼并保存全部」两个主要操作。联系人页面优先展示重要记忆，原始聊天折叠显示。
- 新增 `wechatbrain/analyze.py`：按人、按时间分段分析全部已读取聊天；超长单条消息拆分，保留原消息编号；合并重要要点。
- 提炼重要事实、决定、约定、待办、偏好和重要事件，分类为工作、生活、其他；区分本人、对方、双方与群成员。
- 每条要点必须引用有效原消息编号，保留时间、发言人和原文摘录。无效结果不覆盖已有提炼结果；提示模型不推断完成状态、真实身份或无依据的日期。
- 新增本地提炼缓存。聊天内容与所选模型未变时复用结果；单个人失败后继续处理其他人。
- `export_insights` 生成 `微信第二大脑/人物/` 下的人物重要记忆，以及工作／生活／其他分类索引和总索引。没有重要内容时不生成空人物笔记。
- 点击提炼才向用户配置的模型发送所选聊天。兼容 Chat Completions 接口；API Key 和 iPhone 备份密码只留在当前运行。
- 保留手动修改过的 Obsidian 文件，报告冲突。读取失败与取消结果明确报告。
- Windows x64 便携包包含 Python 官方运行时、桌面窗口与依赖，无需用户安装 Python。

## 已有读取能力

沿用本项目底层提取器，支持 Windows 微信 3.x／4.x 典型数据库结构、数据库目录备份、iPhone Manifest 本地备份（含现代加密备份）和常见 JSON／TXT／CSV／HTML 导出文件。导入时先读取临时快照，保留来源、账号、会话和消息编号，按实际消息去重。

可从选定目录复用可识别的访问材料；Windows 可有界读取当前用户自己的微信进程，以选定数据库验证候选。没有有效访问材料则列出未读文件。无法保证所有微信版本或任意文件夹都能直接读取。
