## 已改动的加载路径

1. **先读聊天，媒体独立准备。** 聊天导入不再扫描并转换整个目录的图片、语音、视频。iPhone 聊天导入只提取数据库和相邻日志；媒体在单独操作中登记位置。
2. **每 500 条提交。** 微信专用表及通用 SQLite 表通过同步批次回调写入本地库；已提交消息可在后台继续读库时查看。SQLite 扫描支持取消，并发布当前文件、记录数、复制字节数、解密页数和耗时。
3. **复用完成文件。** 按读取器版本、账号范围、原文件和 WAL/journal 的大小、修改时间、变更时间、设备与文件身份保存检查点。相同文件下次直接复用已导入结果；未完成的文件重新读取，已落盘消息去重。当前没有变更数据库的逐条游标续传。
4. **保留校验过的私有副本。** 未变化的副本可复用；源文件变化时重新复制和校验。同一批候选与数据库的匹配结果在内存中复用，避免重复执行昂贵的派生校验。双次内容检查、逐页 HMAC、完整日志提交合并和 SQLite 检查仍然保留。元数据缓存不是原子文件系统快照；iPhone 整备份检查点以 Manifest 数据库和 plist 为依据。
5. **控制加载内存。** 专用解析器不再积累全库 Message 列表。无全局消息编号时，重复出现次数使用磁盘临时表，避免为每条消息保留一份全文或内存字典。JSON/HTML/TXT 等旧导出解析器仍可能一次读取整个文件，本轮主要针对微信 SQLite 和备份路径。
6. **媒体按需处理。** 媒体读取先登记路径和大小等元数据。点击预览或明确导出时处理相应文件；预览并发 2、队列最多 32。语音数据库先登记 BLOB 行位置，预览时只读对应语音。单独媒体导出仍会处理所选全部媒体。
7. **轻量进度轮询。** 运行中每秒只读任务内存状态，不再每秒统计全库消息并重复取来源报告。客户端防止轮询重叠；本地 SQLite 改用 WAL 以便读取已提交记录。
8. **读取原程序本地缓存。** 新增独立 `msg_rows` JSON 格式适配，可选择缓存所在目录，复用原程序已解析的数据。仅凭缓存无法确认群名时保留会话 ID；不把群成员昵称当作群名。不执行或分发原程序 EXE、DLL 或商业后台。

## 使用

解压 Windows 便携包，双击“启动京客导出助手.cmd”。已有账号可直接进入；重新读取原记录目录时创建新检查点。0.9.0 的既有库升级后，首次重新读取需要建立 0.10 检查点，之后才可逐文件复用。读取进度出现消息条数后，可点“查看已导入记录”，后台继续读取。

需要附件时打开“媒体文件”，选择同一记录目录后“读取媒体”。列表先出现文件，再点“加载预览”；带附件导出会准备所需文件。iPhone 加密备份重开软件后需要重新填写原备份密码。

私有副本位于 `%LOCALAPPDATA%\WeChatBrain\source-cache`，包含已解密聊天；原始目录保持只读。访问材料、备份密码和 API Key 仍仅保存在运行内存中。不要把自己的本地资料库当作软件发行包分享。

- 这是 75 个媒体文件的位置登记和一个真实预览的耗时，不是图片全部转换耗时，也不是全部聊天数据库加载耗时。原始用户文件未改写。
- 该次操作未导入聊天数据库、未请求 AI、未写入 Obsidian。原程序 msg_rows 格式尚无真实缓存样本验收。
