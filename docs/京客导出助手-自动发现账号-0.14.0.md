# 京客导出助手 0.14.0：自动发现账号

日期：2026-10-25（Asia/Shanghai）。

## 本轮操作约定

用户要求默认操作与参考软件一致，由软件自动分析微信存储位置，不再要求选择文件夹。本轮将默认流程改为：打开助手 → 显示自动发现的账号 → 选择并点击下一步 → 读取 → 自动进入聊天。多个账号需要明确选择，不任意代选另一个账号。手动路径和备份导入移至高级入口。

## REA 原生依据

目标 QXExporter.exe 4.0.9，SHA256 `08ce7e28011db603503718d8fd9f478514931331477c3b5c3ff94efb8870f961`。本轮复用正常 Hopper 试用入口，聚焦以下五个函数：

| 函数 | 地址 | Evidence |
| --- | --- | --- |
| `dbpath.DetectAccounts` | `0x140559f80` | `ev_de70f3f9e1716311ba90e0ce66ae318407a1c5646295650b904793ef949b53ba` |
| `dbpath.CandidateRoots` | `0x1405594c0` | `ev_20c4ebeac9e97bfc2bd622aa38a4cc71638814bacf62ca95b4058237f0b4fe34` |
| `dbpath.windowsConfiguredRoots` | `0x14055bfe0` | `ev_b7aa28040d70ce44caf7ad311675b4fc38227564e6dac78557db17fbd380fc71` |
| `dbpath.scanRoot` | `0x14055a680` | `ev_05b620faa5928ca2deabfb096498f6d49db5a1bf7dd1de573f93bf856d4063e3` |

观察到的调用链：DetectAccounts 汇总 CandidateRoots，去重后调用 scanRoot；CandidateRoots 包含 windowsConfiguredRoots、windowsDocumentDirs 和 windowsDriveRoots；配置路径经过读取、解码、Windows 路径提取，扫描再通过 asAccount 识别账号。函数名称来自 Go 编译元数据映射，原生伪代码不等于原始源码。前端已有状态切片显示账号档案加载、读取进度与账号确认阶段。

本项目独立实现该发现路径与简化操作，不运行或打包原程序。原生证据和会话快照已导出到私有 `.build-cache/qx-research/auto-20261025/`，原生分析会话已正常关闭。

## 发现策略

- 微信 3.x/4.x 用户配置和相关路径注册表。
- Windows 实际文档目录（包含系统重定向/共享文档）、用户目录及 OneDrive 文档候选。
- 固定/可移动磁盘上的常见微信目录；配置中明确给出的网络目录可以检查，不遍历未知网络盘。
- 对已发现的原生账号按实际路径去重。升级用户已有单账号父目录缓存时，折叠该父目录覆盖的重复子账号条目；不同目录中的独立副本不任意合并。
- 扫描在后台进行，限制层级、目录项、配置文件数量/大小与时间预算；不读取聊天内容来发现目录，不递归附件树。配置内容只提取路径，不保存其他字段。
- HTTP 账号列表使用已发现结果快照；重新检测立即安排后台任务。无账号时每 5 秒尝试发现，有账号时每 30 秒检查，扫描中不重复启动。

首次发现只有账号目录标识时先显示该标识；真实名称、备注、头像以经过认证的联系人数据库读取结果为准。

## 已有实际运行证据

环境：Parallels Windows 11 ARM，运行本项目随包的 x64 Python，官方微信 4.1.15.56。使用新建、没有保存过源路径的资料库，既未设置源路径，也未把记录目录作为调用参数。

| 阶段 | 实际观察 |
| --- | --- |
| 启动前 source_paths | 空列表 |
| 首次账号快照 | 约 0.0064 秒返回 scanning |
| 自动发现 | 读取 2 个小型微信配置文件，检查 42 个候选位置，约 0.042 秒找到 1 个原生账号；来源标记为微信配置 |
| 自动选择唯一账号并读取 | 约 2.143 秒，5 个核心数据库，12 条消息、4 个会话，无读取错误 |
| 读取后账号 | 已取得真实账号名称和微信号，状态就绪 |
| 打开已读账号 | 成功，4 个会话、12 条消息 |

本轮数据比 0.13.0 记录时增加，以上数字描述本次实际库内容；不能将差值直接解释为本轮已观察到实时消息到达。实际结果保存在私有 automatic-result.json，不打入发行包。

前端实际查看：使用上述真实资料库的私有备份，将虚拟机共享目录写法映射为同一物理目录在 Mac 上的写法，消息内容与账号身份不变。1180×800 默认窗口尺寸下首页显示自动发现的账号与下一步，未要求输入数据路径；点击下一步直接进入该账号聊天页。开发预览的导出目录使用私有临时位置，自动同步暂停。截图保存在私有 ui-home-0.14.png；这项界面操作与 Windows 空配置自动发现/读取分别记录，不互相替代。

运行核对使用真实账号与本项目程序，没有发送微信消息、改动微信配置、伪造登录或创建合成聊天。未新增或运行自动测试套件。

### 正式便携包运行补充

正式 0.14.0 Windows 便携包已解压并启动原生窗口。另用全新的资料库执行该运行实例的真实 HTTP 接口：启动时 source_paths 为空、消息为 0；账号发现完成后，调用 `/api/accounts/auto-read` 的请求体为 `{}`，没有传入目录或账号 ID。程序自行选择唯一已发现账号，约 3.514 秒读入 12 条消息、4 个会话、5 个核心数据库，错误列表为空；后续打开账号成功。实际收据保存在私有 packaged-auto-result.json。

原生窗口已显示 0.14.0 和自动发现的待读取账号；Windows 系统电量提示遮挡后续点击，当前界面工具未能关闭该提示。本轮不将后端接口操作记作 Windows 界面按钮已逐步点击验收。前述下一步进入聊天的可见操作是在开发预览中完成，两项证据范围保持独立。

## 范围与限制

用户的 `G:\微信聊天记录\WeChat Files` 位于另一台 Windows。本轮加入了自定义路径配置与常见磁盘位置的自动发现，但当前环境不能确认那台电脑实际返回什么配置。目录发现成功与数据库连接/解密成功分开显示，进程正在运行不等于已登录或数据可读。

本次读取仍复用所选账号本机已保存、并经数据库认证的材料；没有现成材料时的首次独立连接兼容性、G 盘大库数量、全部媒体和专用备份读取保留 0.13.0 文档所列边界。本轮不据此宣称所有功能与商业服务完全一致。
