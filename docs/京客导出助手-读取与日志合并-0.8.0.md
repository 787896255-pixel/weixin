### 可直接观察的行为

- `applyWAL` 检查至少 32 字节的头、SQLite WAL 魔数、4096 页大小；每帧跨度 `0x1018`（24 + 4096），比较两段盐，查找非零提交标记，再调用逐页解密覆盖数据库页面。
- `decryptPageInto` 区分第 1 页的 16 字节偏移，使用 CBC 解密，包含 4016 字节位置的 IV 和 4096 页边界处理。
- `DecryptFile` 调用首页候选选择、会话密钥派生、AES 创建、逐页解密和 `applyWAL`，再写输出文件。
- `scanDatabaseKeys` 调用 `acquireScanSession`、`findWeChatPIDs`、`hookSession.inject`、`receiverKeys`、`setLiveHook` 等，支持它包含进程连接与候选接收的判断。
- `ArmEarlyHook` 调用调试权限准备和 `newHookSession`，并准备异步函数；这里只能确认调用关系，不能据此声称底层捕获实现已完整恢复。

## 独立实现

### 记录副本

`wechatbrain/snapshot.py` 复制源文件及相邻 `-wal`、`-journal` 到本次任务的临时目录。

1. 记录主文件及边文件是否存在、设备/文件标识、大小、修改和变更时间。
2. 每次最多读取 1 MiB，复制同时计算 SHA256。
3. 检查文件增删及元数据，再读取源内容计算散列并对比，最后重新检查元数据。
4. 持续变化时最多重试 3 次；失败或取消清理私有副本，原记录不修改。
5. 不复制 SHM，临时目录中的 SQLite 自行重建索引；遇到非空回滚日志明确提示退出微信后重试。

这是用于发现普通并发写入的检查，不能提供原子文件系统快照保证；双次读取增加磁盘 I/O。正在高速写入的目录可能需要正常退出微信再读取。

### 标准加密 WAL

`wechatbrain/wal.py` 按 [SQLite 官方 WAL 格式](https://www.sqlite.org/fileformat2.html#walformat) 独立实现，未复制商业程序代码：

- 检查头、版本、页大小、盐、两种字节序和累积校验。
- 只选择最后一次完整提交；同一页面取该提交之前的最新版本。
- 未提交帧、被截断尾部或旧代日志尾部在报告中说明；本代完整帧校验失败则拒绝本库。
- 只保存页面偏移及散列，不把整个 WAL 读入内存；上限 262,144 帧，超出提示微信合并日志后重试。
- 消费已选页面时再次检查整帧散列，避免索引后内容变化。

`wechatbrain/sqlcipher.py` 将日志页覆盖到临时解密快照，使用数据库页号验证 HMAC，保留首页盐匹配检查，并验证最终 SQLite 完整性。标准 SQLCipher 的 WAL 页使用数据库密钥，首页保留盐，参见 [SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/) 与 [官方 codec 实现](https://github.com/sqlcipher/sqlcipher/blob/master/src/sqlcipher.c)。这里只适配现有页面格式，不意味着能处理任意私有备份或加密配置。

- 账号读取遇到日志、文件变化、页面完整性问题时显示“记录副本需要重新读取”，提供重试入口；不统一归因到重新登录。
