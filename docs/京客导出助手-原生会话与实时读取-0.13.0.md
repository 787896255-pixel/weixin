# 京客导出助手 0.13.0：原生会话与实时读取

日期：2026-10-24；目标平台 Windows x64；开发机为 macOS，实际读取环境为 Parallels Windows 11 ARM 中的 x64 Python 与微信 4.1.15.56。

## 本次需求与定位

用户截图显示两个问题：聊天工作台布局与参考软件不同；目录导入把日期、JSON 文件名等显示为联系人，且缺少原生数据的增量读取。用户已确认截图中的 `G:\微信聊天记录\WeChat Files` 位于另一台 Windows，不在当前可访问虚拟机。

旧导入器把含多个账号的微信总目录识别为普通文件夹，递归读取附件中的 JSON、文本和其他导出文件，生成了不属于原生会话的条目。0.13.0 对微信总目录/账号目录使用独立的数据库选择路径，目录识别失败会报告，不回退到附件扫描。

## 已实现的读取路径

1. `source_plan.py` 在有限层级寻找微信账号，选择联系人、会话、头像和所有匹配的消息分库；不遍历附件内容，不导入微信专用搜索索引。
2. 联系资料、会话与头像从经过认证的私有副本读取。会话按账号和真实 peer ID 关联；缺少名称或头像时保留实际 ID/标准占位，不猜身份。
3. 「全量刷新」重新解析当前会话；「仅读新消息」使用原生消息本地 ID 游标。单会话刷新不会把整个消息分库误记为已全部完成。
4. 自动同步每 3 秒检查当前数据源的数据库、WAL 元数据，只处理发生变化的数据库；界面按同步修订更新当前会话，保持选中项和滚动位置。失败保留旧记录，延时重试；暂停会取消当前后台同步。
5. 冻结读取开始时的 WAL 前缀，校验日志代次、累积校验和完整提交。基础库不变时认证提交页面并更新私有解密副本；更新前记录健康状态与撤销页面，中断/失败需重新建立副本。基础库变化、日志换代、数据库收缩等情况回退完整复制与认证。
6. 头像直接从本地图片 BLOB 提取并通过会话鉴权接口显示。当前页附件按消息证据、MD5/已知文件名和常见账号/月目录查找；歧义不自动绑定。聊天页不等待全量媒体目录登记。
7. 旧版普通文档会话默认隐藏，源记录仍保留。显式导入的普通聊天导出文件继续支持。解析缓存版本升为 13，使升级后原生账号重新经过新读取路径。

源数据库不通过可写 SQLite 连接打开；所有合并与解密写入本机私有缓存。连接材料只在进程内存中保留，诊断仅输出计数和状态。

## 实际运行记录

当前已登录账号与用户截图中的 G 盘账号不同，数据量很小。直接选择其 `xwechat_files` 总目录，实际识别 **1 个账号、5 个核心数据库、4 个会话、12 条本地联系人资料、6 条消息、3 个头像**。没有读取附件 JSON 作为聊天。

| 操作 | 观察结果 |
| --- | --- |
| 初次建立新资料库并读取原生库 | 约 2.260 秒；读入 6 条，无解析错误 |
| 缓存版本升级后重新认证/读取 | 约 2.178 秒；6 条与已有数据去重，无错误 |
| 最新一次复用已认证副本的全量重解析 | 约 0.136 秒；6 条、0 条新增，5 个核心库 |
| 未变化源增量读取 | 约 0.057 秒；5 个文件完成状态复用、0 条新增 |
| 单会话全量刷新 | 任务完成；读到该会话 2 条真实消息，0 条新增 |
| 单会话仅读新消息 | 任务完成；游标后 0 条，未把其他会话条数算进结果 |
| 已有真实加密 WAL 副本更新 | 44 帧、9 次完整提交、13 页、181312 字节；两次约 0.037/0.208 秒 |
| 自动检查循环 | 3 秒间隔已启用并完成，无错误；本次新增 0 条 |

WAL 操作重新应用的是当时已存在的真实提交，未发送微信消息或伪造新增数据。本次没有观察新的外部消息到达，因此不把这个结果称为“新消息到达后界面自动出现”已经验收。

实际结果保存在私有 `native-read-result.json`。执行了 Python AST 与 JavaScript 语法检查；没有新增或运行自动测试套件。
