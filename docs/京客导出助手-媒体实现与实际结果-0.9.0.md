## 原程序调查与 REA 边界

先通过主程序 Go 元数据定位媒体函数，再用 REA `analyze_function` 取得伪代码和汇编。Hopper 对 Go 寄存器调用约定的参数推断存在误差，伪代码不是原始 Go 源码；关键结论结合调用指令、Go 函数元数据和 PE 字符串长度交叉读取。

本轮通过固定版本 REA 6.7.0 新进程请求分析 16 个媒体相关函数。第一次 `open_binary` 绑定后，Hopper 启动器退出码 2，提示 `Cannot launch Hopper! Connection is invalid.`；分析和关闭均返回 `cleanup_incomplete`，保留 `/tmp/rea-Cv1oW9`。原始失败记录在 `.build-cache/qx-research/native/media-20261023/`。

用户提供试用提示截图后，通过正常 “Try the Demo” 进入并观察到 Untitled 空白文档，确认此前目标未保持打开。新批次成功分析 16 个媒体函数，第二批成功分析 8 个图片连接与资源索引函数，两批均导出证据并正常 `close_binary`，后台记录 `verified-cleanup`。证据目录为 `native/media-20261023-retry/` 和 `native/imagekey-20261023/`。没有重新安装组件或修改系统安全设置。

最后补充的初始化、全局材料目录和两个 WXGF 辅助函数请求遇到 Hopper 进程重新启动及再次出现试用提示，界面工具随后返回 ScreenCaptureKit 错误；没有取得这四个函数结果，不计入上述成功数量。保留 `native/media-details-20261023/` 的启动记录，既有成功证据没有覆盖。

该补充请求在 600 秒后返回分析错误，REA 日志已确认所属启动器清理。客户端中断后关闭请求未正常完成，已结束本次独立研究进程，保留 `/tmp/rea-ZN3fdO`。随后通过 Hopper 界面关闭本批次残留的空 `QXExporter.hop`，再次观察到 `Untitled`、0 labels 和 “Hopper is ready”。没有终止其他 REA 会话或 Hopper 之外的用户程序。

实际读取到的行为包括：V1/V2 的 15 字节分段头、AES ECB 与 PKCS7；`aesFromUinWxid` 连接十进制账号编号与微信标识后进行 MD5，以前 16 个十六进制字符作为图片候选；`collectCodes` 从 kvcomm 文件名及下一层目录名收集编号；`kvcommDirsFor` 在所选路径的有限祖先中构造 `net/kvcomm`、`app_data/net/kvcomm`、`xwechat/net/kvcomm`。`verifyAES` 先验证图片块头，完整解码另行进行。

语音数据库查询证据为 `VoiceInfo` 的 `svr_id`，以及 `local_id` 加 `create_time` 后备条件，优先 `data_index` 第一条非空记录。语音识别会在前 64 字节寻找 SILK/AMR 头。资源索引还包含 RecImg 的专门映射，这条映射尚未完整接入，不能把现有 MD5/文件名匹配写成原引擎全部行为。

## 本项目实际实现

### 解码组件与来源

- `wechatbrain/media_codec.py`：图片头与内容验证、旧版 XOR DAT、V1/V2 AES 分段、WXGF HEVC 分段、SILK/AMR 音频及 H.264/AAC 视频转换。
- DAT 与 WXGF 格式适配自 Apache-2.0 Chatlog 源快照 `imldy/chatlog@a7162bca9454fa43b5950a2414670983fe180e56` 的 `pkg/util/dat2img/dat2img.go` 和 `wxgf.go`。保留许可证并记录修改来源，没有复制商业程序代码。
- Windows 包新增 Pillow 12.1.0、pysilk-mod 1.6.4、imageio-ffmpeg 0.6.0。FFmpeg 7.1 是独立开源可执行文件，不来自 QXExporter。许可证和来源见 `THIRD_PARTY_NOTICES.txt`、`third_party/pysilk-mod/` 与 `third_party/ffmpeg/`。
- 不使用开源快照里的 V2 占位密钥。新增 `wechatbrain/image_material.py` 自动查找所选账号目录及当前 Windows 用户的 kvcomm 材料，推导候选并校验 V2 块头，再由解码器完成填充与图片内容校验。明确命名的本地图片材料文件仍可复用。候选、账号编号、图片材料仅留内存；报告只含状态与计数。此本地材料路径尚无真实 V2 样本验收，也没有实现无限穷举或声称全版本自动连接。
- SILK 解码和 FFmpeg 转换在独立子进程中执行，保留超时、取消和原文件；图片读取限制大小、尺寸和动图帧数。补充语音前缀清理、WXGF 内嵌标准图片校验和 TIFF 首帧转 PNG，便于 WebView2/HTML 显示。

### 接入软件

- 新增本地媒体缓存、资源列表、逐消息媒体标识和附件关联表。源文件不改写。
- 保留消息中的 MD5、文件标识，再与所选目录中的资源关联。没有证据的文件不自动分给联系人；同名不同内容的候选不强行匹配。
- 页脚新增“媒体文件”，可以单独读取、查看和导出所选目录的媒体；数据库暂未读出时也能使用。
- 聊天内可显示图片、播放已解码音视频、下载文件；媒体接口检查本机会话，并提供分段读取用于音视频跳转。
- HTML/Markdown/PDF/JSON/表格/文本导出加入附件路径和状态；实际文件写入独立 `media/` 目录，HTML 使用相对路径显示/播放。
- iPhone Finder/iTunes 提取可包含常见图片、音视频文件；专用微信备份提示先在电脑版微信恢复，再读取实际账号目录。

新增 `wechatbrain/media.py`、`wechatbrain/media_codec.py`、`wechatbrain/image_material.py`、`web/media.js`；修改 `app.py`、`store.py`、`importer.py`、`archive.py`、`chatlog_platform.py`、`chatlog_extract.py`、前端 HTML/JS/CSS、依赖、版本、使用说明及第三方声明。修改前备份在 `.build-cache/qx-research/before-0.9.0/`。
